# Milestone M4 — Seed Pack: Initial Agents, MCP Server, Tools & Skills Simulating EPM Copilot Outcomes

**Precondition:** M3 accepted.
**Goal:** the Console ships populated. The seeded configuration reproduces the existing EPM Copilot outcome set — grounded chat with citations plus the SoW / Requirements / Design / Test-Script accelerators — entirely as Console-managed data, runnable in the Playground on day one. Seed definitions live in `seeds/` (samples provided; refine, don't replace their structure).

## Tasks

1. **Seed loader:** idempotent script (`pnpm seed:ai-console`) reading `seeds/*.json` and `seeds/skills/*.md` → creates/updates entities by slug; safe to rerun; tenant-aware; writes audit entries (`actor: seed-script`).
2. **MCP & tools:** register `knowledge-mcp` (managed) per `seeds/mcp-servers.sample.json`; sync its 4 tools; seed internal tool records per `seeds/tools.sample.json`.
3. **Skills (from `seeds/skills/`, one .md each, knowledge-linked to the seeded KC):**
   - `sow-writing` — SoW structure, scope language, assumptions/exclusions discipline, estimation framing.
   - `requirements-elicitation` — software-aware requirement capture, MoSCoW, the questionnaire pattern from the existing Requirements accelerator.
   - `functional-design-writing` — FDD structure mapped to EPM software capabilities (KC-grounded terminology).
   - `test-script-writing` — UT/SIT/UAT case structure: preconditions/steps/expected/data.
   - `grounded-chat` — NotebookLM-style answering: cite KC anchors, admit weak grounding, never fabricate.
4. **Output schemas:** seed `sow.v1`, `requirements.v1`, `design.v1`, `test_scripts.v1` (sections + items, citation slots) in `output_schemas` — Zod-mirrored.
5. **Agents (per `seeds/agents.sample.json`):**
   - `copilot-chat` (purpose: chat) — grounded-chat skill; tools: kc.search/get_section; no output schema.
   - `sow-composer` — sow-writing skill; schema sow.v1.
   - `requirements-accelerator` — requirements-elicitation; schema requirements.v1.
   - `design-composer` — functional-design-writing; schema design.v1.
   - `test-script-composer` — test-script-writing; schema test_scripts.v1.
   All: model routing onto an existing `llm_providers` record; allowed tools restricted to knowledge-mcp; citation discipline in every system prompt.
6. **Golden playground fixtures:** 5 saved example inputs (one per agent) — e.g., a consolidation-scope brief for `sow-composer` — so "Run example" works instantly; expected-behaviour notes per fixture in `seeds/README.md`.
7. **Docs & tour:** `docs/ai-console-admin-guide.md` finalised (create/edit/version/activate each entity; register an external FastMCP server; add a skill linked to new knowledge; promote via Playground); driver.js mini-tour of the Console (Dashboard → create skill → wire into agent → Playground run → activate); `docs/extending-ai-console.md` (add a new agent/skill/tool/MCP server/schema — exact steps, referencing the seed files as canonical examples).
8. **Tests:** seed idempotency (run twice → no dupes, versions stable); each seeded agent passes a smoke Playground run (schema-valid where applicable, ≥1 citation).

## Acceptance Checks

- [ ] Fresh DB → migrate + seed → Console shows 5 agents, 5 skills, 1 healthy MCP server with 4 tools, 4 internal tool records, 4 schemas.
- [ ] Run all 5 golden fixtures in the Playground: `copilot-chat` answers with KC citations; the 4 composers emit schema-valid structured outputs with cited sections grounded in the OneStream KC.
- [ ] `sow-composer` output visibly reflects the `sow-writing` skill (e.g., assumptions/exclusions present) — change the skill, rerun, observe the change.
- [ ] Seed rerun is a no-op (show entity counts before/after).
- [ ] New admin completes the Console tour: creates a skill linked to a KC section, wires it into a copy of `copilot-chat`, tests in Playground, activates — unaided.
- [ ] Full legacy regression passes. CI green.
