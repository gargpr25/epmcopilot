# Milestone M3 — Playground

**Precondition:** M2 accepted.
**Goal:** a first-class testing surface inside the Console where any agent + skill + knowledge binding can be exercised against real inputs, with full observability — the daily driver for tuning configs before they touch project work.

## Tasks

1. **Run composer (left panel):** select Agent (active version default; any version selectable) → effective Skills shown (override/add for this run only) → **knowledge binding scope**: default = the agent's skills' knowledge_links; user may narrow/expand to specific KCs/versions/tags for the run → input area: free prompt, optional structured fields when an output schema applies, optional file/context upload (sanitised) → run parameters (temperature/max_steps overrides, clearly marked as run-only).
2. **Live run view (right panel):** SSE streaming — step timeline (retrieval steps with chunk previews + scores, tool calls with args/results, LLM calls with token counts), then the output: rendered markdown / schema-validated JSON viewer, **citations rail** (click anchor → opens the KC section, highlights the chunk), warnings (weak grounding statements, blocked tool attempts, validation retries).
3. **Run record & history:** every run persisted (`playground_runs`); **Runs** tab: filter by agent/skill/user/date/status; run detail page = same view as live; cost + latency shown; rerun button (same inputs, current active versions) and **pin-versions rerun** (exact reproduction).
4. **Compare mode:** select two runs (e.g., same input, agent v1 vs v2) → side-by-side outputs with diff, plus deltas in tokens, cost, latency, citation counts.
5. **Promote loop:** from a satisfactory draft-version run → one-click "Activate this version" (Admin, audited). From any editor, "Test in Playground" opens the composer pre-loaded with that entity.
6. **Safety rails:** Playground runs are tenant-scoped, rate-limited (reuse existing limiter pattern), capped per-run token budget with honest halt, and clearly excluded from any project/deliverable data (no HOTL bypass — Playground outputs are not exportable as client deliverables).
7. **Tests:** run persistence completeness (every step traced); citation-anchor resolution; compare-diff correctness; version pinning reproduces composed prompt byte-identically; budget halt.

## Acceptance Checks

- [ ] Run the M2 test agent from the Playground: streamed timeline, output with ≥2 clickable citations resolving to real KC sections.
- [ ] Narrow knowledge binding to one KC → retrieval steps show only that KC's chunks.
- [ ] Edit agent prompt → new draft version → run draft in Playground → compare vs active version side-by-side → activate draft from the compare view; audit entry written.
- [ ] Pin-versions rerun of an old run reproduces the identical composed prompt (show hash).
- [ ] Tiny token budget on a run → honest halt with partial trace.
- [ ] Playground content nowhere reachable from project deliverable/export paths (demonstrate). Existing flows regression-pass; CI green.

**STOP — do not start M4.**
