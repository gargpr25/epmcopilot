# Milestone M2 — Runtime: knowledge-mcp Server + Agent Executor

**Precondition:** M1 accepted. Execute against `GAP_MAP.md`.
**Goal:** the things the console manages become executable. One managed FastMCP server over the existing Knowledge Cartridges; an Agent Executor that runs active agent configs with real LLM calls through the existing provider layer/keys.

> **TESTS FIRST** for: allow-list enforcement, citation extraction, schema-validate-with-retry, prompt composition order.

## Tasks

1. **`knowledge-mcp` (managed, FastMCP/Python per original Ph-5 design):**
   - Tools: `kc.list`, `kc.search(query, kc_ids?, tags?, top_k)` (hybrid vector+keyword), `kc.get_section(kc_id, anchor)`, `kc.get_component(kc_id, component_id)`.
   - Index per the M0 decision (LanceDB per-KC **or** pgvector — one only). Ingest/refresh job indexes existing KC content (start with the OneStream KC; structure for N).
   - Containerised; `/health`; docker-compose entry consistent with current dev setup; auto-registers in `mcp_servers` (managed=true) on boot.
2. **MCP client + registry liveness (TS, in API):** connect by registry row; **health checks** (periodic + on-demand button from M1 now live) updating status/last_health_at; **tool discovery** populating `tools` from the server's tool list (manual sync button + on-register); sandbox single-tool call from the MCP Servers tab (Admin only, logged).
3. **Agent Executor (per M0 placement decision):**
   - Load active `agent_config_version` → compose prompt in the canonical order (CLAUDE.md §4.3) resolving `{{skill:slug}}` to active skill versions and injecting each skill's knowledge_links as retrieval hints.
   - Tool loop: agent may call only `allowed_mcp_tools`; out-of-list calls blocked + logged; max_steps enforced; timeouts/retries on MCP calls.
   - LLM calls via the **existing provider abstraction and credential refs** (no new env keys — acceptance will grep); region allow-list enforced; every call → `llm_call_records`.
   - Output handling: if output_schema set → validate, bounded retry on invalid, honest failure surfaced; citation parser extracts KC anchors per claim/section; full ordered step trace (retrievals with chunk ids/scores, tool calls with args/results, LLM calls with token counts) persisted to `playground_runs`.
   - Untrusted-input handling per CLAUDE.md §4.4.
4. **Hot reload proof:** executor always reads the *currently active* versions at run start — no caches that survive activation changes.
5. **Tests (first):** the four named above, plus: tool-discovery sync idempotency; health transitions; executor reproducibility under pinned versions; regression of all existing flows.
