# Milestone M1 — Registries + AI Console CRUD (Agents, Skills, MCP Servers, Tools, Schemas)

**Precondition:** M0 accepted. Execute against `GAP_MAP.md` / `EMBEDDING_PLAN.md`.
**Goal:** the full management surface exists — create/update/delete/version everything — even before the runtime (M2) can execute it. Honest state: "Run in Playground" buttons visible but disabled with "runtime arrives in M2" tooltip (no fake runs).

## Tasks

1. **Migrations (additive):** `agent_configs`(+versions), `skills`(+versions), `mcp_servers`, `tools`, `output_schemas`, `playground_runs` per CLAUDE.md §3 — tenant_id everywhere, FKs to existing `knowledge_cartridges` and `llm_providers`.
2. **API:** CRUD + lifecycle routes under `/api/v1/ai-console/*` using the existing route/guard/tenant/audit patterns (named in EMBEDDING_PLAN). Lifecycle: create draft → edit → publish version → activate → archive; rollback = activate prior version; delete only for drafts/archived (soft delete). Every mutation → audit_log. Zod request/response schemas in `packages/shared-types` (start the Zod layer properly here).
3. **Console UI** (per EMBEDDING_PLAN: inside existing apps/web admin area, or as the founding screens of apps/web behind the minimal shell):
   - Shared scaffolding: list pages with search/filter/status chips; editor drawers/pages; version history with side-by-side diff; activate/rollback; feature flag `AI_CONSOLE_ENABLED`.
   - **Agents:** editor with system-prompt editor (supporting `{{skill:slug}}` includes with live preview of the composed prompt), model routing picker (from existing `llm_providers` — region allow-list visible), skills multi-select, allowed-MCP-tools picker (from `tools`), output-schema select, max_steps/temperature.
   - **Skills:** markdown editor with preview; **knowledge-link picker** browsing existing KCs → versions → sections/components/tags; linked-knowledge panel showing resolved targets; staleness badge when a linked KC has a newer version.
   - **MCP Servers:** register (name, url, transport, auth_ref — reference string only), enable/disable; health and tool-discovery buttons present but inert-with-tooltip until M2.
   - **Tools:** list grouped by server; enable/disable; description/input-schema view; internal (non-MCP) actions section.
   - **Output Schemas:** JSON-schema editor with validation and example-payload tester (pure client-side validation — this can be fully live now).
4. **Dashboard tab:** entity counts, recent changes feed (from audit), placeholder health panel.
5. **Tests:** version immutability + activation pointer; rollback; tenant isolation on every console route (cross-tenant read must 404); audit entries per mutation; KC-link resolution incl. staleness detection.
