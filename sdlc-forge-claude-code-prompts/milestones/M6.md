# Milestone M6 — Telemetry Reports & Multi-Format Exports

**Precondition:** M5 accepted. Read `CLAUDE.md` and `ARCHITECTURE.md` first.
**Goal:** every output has a one-click telemetry report and downloads as DOCX, PDF, and PPTX rendered deterministically from golden templates.

> **TESTS FIRST** for the rendering pipeline: placeholder-mapping fixtures and round-trip assertions before implementation. (CLAUDE.md §2.7.)
> **Real template required:** ask the human for at least one genuine golden .docx template (e.g., real SoW format) before building the mapper; do not proceed with only synthetic templates.

## Tasks

1. **Golden-template mapper**: Admin uploads a .docx/.pptx template; system detects placeholders (`{{section:executive_summary}}`, `{{table:requirements}}`, `{{rtm}}`, `{{meta:client_name}}`…); mapping UI binds placeholders to schema fields; validation flags unmapped mandatory placeholders; preview render with sample data.
2. **RenderService (deterministic, queued via BullMQ):**
   - DOCX: `docx` npm against the mapped template — styles, headings, tables (requirements, WBS, test cases, RTM), headers/footers, TOC, document-control page (version, manifest version, approval trail).
   - PDF: LibreOffice headless conversion of the rendered DOCX (single source of truth).
   - PPTX: `pptxgenjs` against a slide template — executive summary deck per output (key sections, coverage stats, anomaly summary).
   - `exports` rows with checksum; signed download URLs from MinIO/S3.
3. **Anomaly engine completion**: consolidate all anomaly producers; severity model; resolution workflow (acknowledge / resolve with note / false-positive); anomaly history on the item.
4. **Per-output Telemetry Report** (ReportAgent + telemetry-mcp), viewable in-app and exportable (DOCX/PDF):
   1. Background — project, phase, manifest version, agent/model/config versions, timestamps.
   2. Inputs & outputs statistics — documents consumed (count/pages/chunks), guided answers used, sections generated, items minted/linked, tokens and cost, duration.
   3. Knowledge usage map — per-section cited artifacts/chunks with relevance; tree-branch contribution heat map; **unused bound knowledge** list.
   4. Anomalies & conflicts — full list with evidence and resolution status.
   5. Traceability summary — coverage %, orphans, broken chains.
   6. Citations appendix with deep links.
5. **Exports UI**: per-output download menu (DOCX/PDF/PPTX/Report) with render status, retry, and checksum display.
6. **Tests** (first): placeholder extraction; mapping completeness validation; deterministic render (same input → same checksum); RTM table correctness in DOCX; report statistics accuracy against fixture runs.
