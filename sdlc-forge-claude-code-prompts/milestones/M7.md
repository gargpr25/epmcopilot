# Milestone M7 — Enterprise Polish, Eval Harness, Tutorials & Final Seed

**Precondition:** M6 accepted. Read `CLAUDE.md` and `ARCHITECTURE.md` first.
**Goal:** demo-ready, governable, and self-onboarding. A new user or admin can succeed guided only by in-app tours and docs.

> **TESTS FIRST** for the eval harness scoring logic. (CLAUDE.md §2.7.)

## Tasks

1. **Eval harness**: `eval_cases` = golden inputs + expected-output assertions (mandatory sections present, citation density threshold, traceability coverage threshold, schema validity, no critical anomalies). `eval_runs` execute the full pipeline on a sandbox copy. Admin UI: run evals on demand and automatically when an agent config or knowledge artifact version is promoted; promotion is blocked on regression (with override + audit). Seed ≥5 eval cases from NovaBank.
2. **Cost governance**: per-project and per-tenant token budgets (`cost_budgets`); soft-warning and hard-stop thresholds; cost dashboard (by project, phase, agent, model, time); model-routing rules editable in Admin.
3. **Collaboration & workflow**: section-level comments with @mentions; review assignments; approval sign-off capture (name, timestamp, version hash); notifications (in-app + email stub) for phase-ready, review-requested, anomaly-threshold, budget-threshold.
4. **Version diff**: visual diff between any two versions of an output (section-level, word-level highlighting) with the run/config metadata of each side.
5. **Audit log viewer** in Admin: filterable by user, entity, action, date; export.
6. **Tutorials (driver.js):**
   - **User tour (10 steps):** create project → review/freeze binding → upload phase inputs → answer guided questions → generate (watch agent timeline) → review citations & anomalies → edit/regenerate a section → approve → view RTM → export DOCX/PDF/PPTX + report.
   - **Admin tour:** add a knowledge artifact into the taxonomy → upload & map a golden template → edit an agent config and sandbox-test it → register an MCP server and check health → run an eval before promoting.
   - Tours launchable from a persistent Help menu; first-login auto-offer per role; "Ask about this tool" helper panel answering from `/docs` content.
7. **`/docs` help centre**: user guide, admin guide, `docs/extending.md` (add knowledge, templates, schemas, agents, MCP servers, models, question banks — exact steps), troubleshooting, glossary (REQ/FDD/TDD/WBS/TC, manifest, anomaly types).
8. **Final seed pass** per CLAUDE.md §8: verify the finished NovaBank project, empty project, full taxonomy, all roles' demo users, question banks, eval cases.
9. **Accessibility & polish**: WCAG AA audit fixes; keyboard navigation; empty/loading/error states everywhere; final EY-theme consistency sweep; Lighthouse pass on key pages.
10. **Hardening checklist** (verify, fix gaps): rate limiting, OWASP basics, idempotent jobs, secrets hygiene, OpenAPI published, >80% coverage on the four cores, clean-clone `docker-compose up`, CI green. Record any residual gaps honestly in `KNOWN_GAPS.md`.

## Acceptance Checks (run and print results)

- [ ] Eval suite runs; deliberately degrade an agent prompt → promotion blocked with regression report; restore → promotion passes.
- [ ] Hard budget stop: set a tiny budget on a test project → generation halts with a clear message and notification.
- [ ] A fresh user account completes the entire user tour and produces an exported SoW with no outside help (walk through it yourself and report friction).
- [ ] A fresh admin account adds a new knowledge artifact via the admin tour, re-binds the test project, regenerates a section, and sees the new artifact cited.
- [ ] Diff view between two BRD versions highlights the edited section.
- [ ] Audit viewer shows the full trail for one project lifecycle.
- [ ] Clean clone → `docker-compose up` → seeded demo works end-to-end; CI green; coverage report ≥80% on traceability, binding, rendering, schema-validation packages.
