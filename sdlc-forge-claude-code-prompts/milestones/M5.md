# Milestone M5 — Externalised Agents & MCP Layer

**Precondition:** M4 accepted. Read `CLAUDE.md` and `ARCHITECTURE.md` first.
**Goal:** agent behaviour and tool access are data, not code. Five MCP servers run as separate processes; agents call tools through MCP; everything is administrable without redeploy.

## Tasks

1. **Build the five MCP servers** (`apps/mcp/knowledge`, `document`, `traceability`, `telemetry`, `export`) with the TypeScript MCP SDK, exposing the tools listed in CLAUDE.md §7. They wrap the existing services — no business-logic duplication. Each has health endpoint, auth (shared-secret/JWT), and docker-compose entries.
2. **MCP registry**: `mcp_registry` rows per server (url, auth ref, status); periodic health checks; tool discovery (list tools + schemas) stored in `discovered_tools`; Admin UI to register/edit servers, view health history, browse discovered tools, and run a single tool call in a sandbox.
3. **Rewire agents**: LangGraph agents resolve their `allowed_mcp_tools` from `agent_configs` and invoke via MCP clients. Tool-permission enforcement: an agent calling a tool outside its allow-list is blocked and logged.
4. **Agent config Admin**: editor for system_prompt, model, temperature, max_steps, allowed tools (picker from discovered tools); config versioning with diff view; **sandbox test-run** (run an agent against a chosen project/phase in dry-run mode, see the full step trace, no writes committed); activate/rollback versions. Generation runs record the exact agent-config versions used.
5. **Tool/action registry**: catalogue of non-MCP internal actions (render, notify, export) with the same admin visibility.
6. **Resilience**: MCP call timeouts, retries with backoff, circuit-breaker; an unhealthy server fails generations gracefully with an honest error and an anomaly/notification.
7. **Tests**: tool-permission enforcement; registry health-state transitions; agent run reproducibility given pinned config versions.

## Acceptance Checks (run and print results)

- [ ] All five MCP servers run as separate containers; Admin shows them healthy with discovered tool lists.
- [ ] Edit the DocumentComposer system prompt in Admin (e.g., "always include an Assumptions subsection") → next generation reflects it, **no redeploy**; the run records the new config version.
- [ ] Sandbox test-run shows a full step trace and writes nothing (verify DB).
- [ ] Kill the knowledge-mcp container → Admin shows unhealthy; a generation attempt fails gracefully with a clear user-facing error; restart restores health.
- [ ] An agent attempting a tool outside its allow-list is blocked (test evidence).
