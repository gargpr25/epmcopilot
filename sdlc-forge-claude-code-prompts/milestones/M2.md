# Milestone M2 — First Generation Chain (SoW → BRD)

**Precondition:** M1 accepted. Read `CLAUDE.md` and `ARCHITECTURE.md` first.
**Goal:** the full generation loop works for two document types: phase inputs → gap-analysis Q&A → grounded generation with citations → review/edit → approval → next phase consumes the approved output.

## Tasks

1. **Phase pipeline UI**: horizontal phase stepper on the project page (SoW → BRD → FDD → TDD → Dev Plan → Test Scripts), with statuses from `phases`. Only SoW and BRD are active in this milestone; later phases render as locked with honest "available in a later milestone" states (rule: no fake buttons).
2. **Phase inputs**: per-phase upload area (reuses M1 parse/chunk/embed pipeline into `phase_uploads`/`upload_chunks`); prompt-injection sanitisation per CLAUDE.md §2.5; list/preview/delete.
3. **Document schemas + skills + templates**: author real `doc_type_schemas` (Zod + JSON Schema) for SoW and BRD; seed an output-document skill and a golden-template metadata record for each (placeholder mapping done in M6; structure mapping now).
4. **Agent layer v1 (in-process LangGraph; MCP externalisation happens in M5):**
   - `KnowledgeRetriever`: hybrid retrieval scoped strictly to the project's frozen manifest.
   - `GapAnalyst`: compares template-mandatory sections vs available inputs → writes `guided_questions`; UI renders a structured Q&A form; answers stored in `guided_answers`.
   - `DocumentComposer`: generates section-by-section JSON valid against the schema, each section carrying `section_citations` to real chunk IDs (artifact chunks, upload chunks). Retry-on-invalid-schema with bounded attempts.
   - `PhaseOrchestrator`: sequences retrieve → compose → validate; persists `generation_runs` with tokens/cost/duration/OTel trace.
   - Provider-agnostic LLM layer with per-agent model routing read from `agent_configs` (seed configs for all agents now).
5. **Live progress**: SSE stream of agent steps to a timeline panel during generation.
6. **Review editor**: side-by-side — generated document (sectioned, inline-editable) left; right rail tabs for Citations (click → opens source chunk with highlight) and Run info. Regenerate-a-single-section action. Output versioning on edit/regenerate.
7. **Approval gate**: Reviewer role approves; approved output becomes immutable version; BRD generation consumes the approved SoW JSON via `get_prior_output` semantics.
8. **Seed**: 3 NovaBank sample client uploads; question bank entries for SoW/BRD.
9. **Tests**: schema validation (valid/invalid/retry), citation integrity (every citation resolves to an existing chunk), manifest-scoping of retrieval (a chunk outside the manifest is never cited).

## Acceptance Checks (run and print results)

- [ ] On the seeded NovaBank project: upload inputs → GapAnalyst produces ≥5 sensible guided questions → answer them → generate SoW with live agent timeline.
- [ ] Every SoW section shows ≥1 citation; clicking 3 random citations opens real source chunks containing the cited basis.
- [ ] Attempt generation with a deliberately broken schema → bounded retries → honest failure surfaced, run marked failed.
- [ ] Edit a section, regenerate another section: version history shows both, prior versions readable.
- [ ] Approve SoW as Reviewer; generate BRD; BRD content demonstrably uses SoW content (cites it).
- [ ] Retrieval-scoping test green: knowledge outside the manifest is never retrieved or cited.
- [ ] Contributor cannot approve (server-side). CI green.
